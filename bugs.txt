1. In `app/backend/src/knowledge_base.py`, during vector chunk preparation (`chunk.metadata['owner_id'] = str(owner_id)`), `owner_id` is stored as a string. However, in `app/backend/src/runner.py`, the retrieval query uses `ObjectId(owner_id)` for filtering (`"owner_id": {"$eq": ObjectId(owner_id)}`). This type mismatch will prevent the RAG system from finding any chunks in MongoDB.
2. In `app/backend/src/agent.py` under the `delete_agent` function, the query searches for `"owner_id": str(current_user["_id"])` when deleting from `agents_collection`. Agents are originally created with `"owner_id": ObjectId(current_user["_id"])`. This will prevent users from deleting their agents.
3. In `app/backend/src/agent.py` under the `update_agent` function, the `$set` payload misses updating some fields if they are `None` due to `exclude_none=True`, but when generating the return dictionary, it attempts to access `updated["updated_at"]` etc., but if the agent wasn't found it returns earlier, so this is partially fine, except if some data inherently holds `None` it won't be cleared. But primarily the object ID search is handled well here.
